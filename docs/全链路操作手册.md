# X-AnyLabeling 全链路操作手册

从「导入图片」到「人工标注」，到「用 X-AnyLabeling 调模型训练」，再到「导出模型 / 导出标注」。
每一步的菜单路径、要填的字段、实测数字都写在这里，可直接照着做。

环境：Windows 11 · Python 3.12.16（uv 托管）· X-AnyLabeling 4.3.1 · torch 2.15.0+cpu · ultralytics 8.4.218 · GTX 1650（无 CUDA，全部走 CPU）

1. **92 ≠ 1206**。X-AnyLabeling 只认 `.json`，而 1206 张里只有 92 张配了 `.json`，其余 1114 张只有 YOLO `.txt`，要在软件里看必须先用脚本转格式（本仓库没做，也没必要——看图用 demo/demo2 的 92 张就够）。

## 1 导入图片

标注软件打开方式：桌面 `X-AnyLabeling 标注演示.lnk`（已定位到 `demo2\images`），或直接跑 `xanylabeling.exe`（在你装 X-AnyLabeling 的环境里）。

| 操作 | 菜单路径 | 快捷键 |
|---|---|---|
| 打开整个文件夹 | **文件 File › 打开文件夹 Open Dir** | `Ctrl+U` |
| 打开单张图 | **文件 File › 打开文件 Open File** | `Ctrl+I` |
| 打开视频逐帧抽 | 文件 File › 打开视频 Open Video | `Ctrl+O` |

导入规则（实测）：

- 只加载扩展名匹配图片的文件，**会自动配对同名 `.json`**；没有 json 的图会被当成「未标注」。
- 图片在哪，json 就存哪。如果目录是只读的（比如 `D:\图片` 的那种 ACL 只读），保存会失败——换到可写目录，或用 **文件 › 更改输出目录 Change Output Dir** 把 json 写到别处。
- 状态栏显示 `[未验收]` / `[已验收]`；按 `Ctrl+Alt+K` 切换验收标记，`[1/60]` 是当前序号。

## 2 人工标注

| 操作 | 快捷键 | 说明 |
|---|---|---|
| 画矩形框 | `R` | 最常用，本项目全部用矩形 |
| 画多边形 | `P` | 分割任务才用 |
| 改标签 | `Ctrl+E`（或双击框） | 从已有标签里挑，或直接输入新标签 |
| 删除框 | `Delete` | |
| 复制/粘贴框 | `Ctrl+C` / `Ctrl+V` | 同图内复制 |
| 撤销 | `Ctrl+Z` | |
| 下一张 / 上一张 | `D` / `A` | 翻页看标注结果 |
| 下一张未验收 | `Ctrl+Shift+D` | 快速找没标完的 |
| 保存 | `Ctrl+S` | 配置里 `auto_save: true`，画完自动存 |
| 打开设置 | `Ctrl+0` | |

标注规范（本项目口径，5 类）：

1. **人**：整个人体轮廓，从头到脚，别把腿切掉。
2. **安全帽**：只框帽体本身，不含头部/头发。
3. **未戴安全帽**：露出的头部（含头发），帽子缺失时才标。
4. **反光背心**：只框背心区域，不含手臂。
5. **未穿反光背心**：躯干衣服区域，没穿背心时才标。

判定思路：一张图里「人」是主体，其余四类都是人的属性。所以同一个人身上，要么「安全帽」要么「未戴安全帽」，二者只出现一个；背心同理。这个规则和后面训练、合规判定完全一致，标注时必须守住，否则训练出来的模型互相打架。

## 3 自动标注（用现成模型先跑一遍，再人工修）

| 步骤 | 操作 |
|---|---|
| 1 | 打开图片文件夹后，按 **`Ctrl+A`**（Auto Labeling）打开右侧 AI 标注面板。也可以**在画布上右键**，菜单里有「自动标注 Auto Labeling」；工具栏上那个**大脑图标**就是它。 |
| 2 | 面板顶部的模型下拉框，选 **PPE 工地安全帽/反光背心 (YOLOv8n)**（原始模型）或 **PPE 演示训练模型 (YOLOv8n, 8 轮 CPU)**（自己训练的） |
| 3 | 面板里两个滑块：`Confidence`（本项目 **0.35**）、`IoU`（**0.45**） |
| 4 | 点蓝色按钮 **`Run (i)`** —— 只跑当前这张 |
| 5 | 点 **`Clear (b)`** 清掉不想保留的框；**`Finish (f)`** 结束本次会话 |
| 6 | 跑完人工增删改，`Ctrl+S` 保存 |

**批量跑整个文件夹**：`Ctrl+B`（`Run All Images`），会把目录里所有图都过一遍模型。按钮文字是英文 `Run (i)` / `Clear (b)` / `Finish (f)`，快捷键就是括号里那个字母。

> 注意 `工具 Tool` 菜单里**没有**自动标注（那里是概览、另存裁剪、标签管理、形状转换等）。自动标注只在 **`Ctrl+A`／工具栏大脑图标／画布右键菜单** 三处。

⚠️ 自动标注会**覆盖**当前 json（面板上没有 `Replace (On)` 时）。批量跑 `Ctrl+B` 之前先把 json 复制到别处备份。

## 4 用 X-AnyLabeling 调模型训练

菜单：**训练 Train › Ultralytics**（这是 `Train` 菜单下唯一一项）。弹出三页签对话框。

### 4.1 Data 页

- 任务类型选 **Detect**（目标检测）。
- `Dataset Summary:` 会显示当前目录下已标注/未标注数量，确认数字对得上再往下走。

### 4.2 Config 页（逐个字段，照填）

| 字段 | 填什么 | 说明 |
|---|---|---|
| `Project:` | `<仓库>\runs` | 训练产物落盘的父目录 |
| `Name:` | `demo_train` | 子目录名，产物在 `runs\demo_train\` |
| `Environment:` | `<装了 torch + ultralytics 的 python.exe>` | **必须**指向装了 torch+ultralytics 的解释器，留空会用软件自己的解释器（那个没装 torch，直接报 `torch_missing`） |
| `Model:` | `<仓库>\weights\yolov8n.pt` | 预训练起点；要先有 `yolov8n.pt`（6.5 MB） |
| `Data:` | `<仓库>\data.yaml` | 现成数据集描述文件，填了它就不会现场生成数据集 |
| `Device:` | `cpu` | 本机无 CUDA，选 cuda 会失败 |
| 数据集划分滑块 | 80 | 只在「没有现成 data.yaml」时才生效 |

> 如果 `Data:` 留空，软件会**现场**把当前打开目录的 json 按滑块比例切成 `images/train,val` + `labels/train,val` + 自动生成 `data.yaml`。这也是一条可用路径，适合临时标了几十张就想试训一次。

`data.yaml` 的内容（已在仓库里备好）：

```yaml
# path 省略 = 以 data.yaml 所在目录为根
# path: <仓库>
train: train/images
val: valid/images
test: test/images
nc: 5
names: 0 helmet, 1 no-helmet, 2 no-vest, 3 person, 4 vest
```

**类别顺序必须和这里一致**，后面导出、接回自动标注都靠它对齐。

### 4.3 Train 页（本项目实测参数）

| 字段 | 值 | 为什么 |
|---|---|---|
| `Epochs:` | `8` | CPU 上一轮 34 秒，8 轮够看到 mAP 收敛趋势 |
| `Batch:` | `8` | 4 GB 显存无关（走 CPU），内存 16 GB 够 |
| `Image Size:` | `416` | 640 一轮要 44 秒，416 快一倍，精度损失可接受 |
| `Workers:` | `2` | Windows 上多了容易卡 |
| `Classes:` | 5 | |
| 高级设置 › `Fraction` | `0.25` | 只用 25% 训练集，把 8 轮压到 4.5 分钟 |

填完点 **开始训练 Start Training**。日志窗口会打印 `Training command: yolo detect train data=... model=... epochs=8 ...`，可以对照检查参数有没有传对。

### 4.4 实测结果（`runs/demo_train`）

总耗时 **272.5 秒**（约 4 分 33 秒），每轮 34 秒。

| Epoch | mAP50 | mAP50-95 |
|---|---|---|
| 1 | 0.4171 | 0.2206 |
| 2 | 0.5041 | 0.2661 |
| 3 | 0.5632 | 0.2918 |
| 4 | 0.6423 | 0.3422 |
| 5 | 0.6720 | 0.3662 |
| 6 | 0.6501 | 0.3511 |
| 7 | 0.6843 | 0.3678 |
| **8** | **0.7168** | **0.3941** |

末轮 P 0.677 / R 0.689。产物：`weights\best.pt`、`weights\last.pt`，以及 `results.csv`、`results.png`、`BoxPR_curve.png`、`confusion_matrix.png`、`val_batch*_pred.jpg` 等可视化。

> 这个 0.7168 是在 25% 训练集、8 轮、416px 下的数字，**不能**和网页里 0.5401 的基线混着比——那是在完整 1206 张上评估一个商用权重的结果。两者口径不同。

## 5 导出模型

### 5.1 从训练结果导出（推荐路径）

训练结束后，`Train` 页右下角出现 **导出 Export** 按钮 → 弹 `ExportFormatDialog`，14 种格式：

| 格式 | 值 | 适用 |
|---|---|---|
| ONNX | `onnx` | **本项目用这个**，跨平台、onnxruntime 直接跑 |
| TorchScript | `torchscript` | 纯 Pytorch 部署 |
| OpenVINO | `openvino` | Intel CPU 加速 |
| TensorRT | `engine` | NVIDIA GPU（本机没 CUDA，不可用） |
| CoreML | `coreml` | Apple |
| TFLite / Edge TPU / TF.js | `tflite` / `edgetpu` / `tfjs` | 移动端 / 浏览器 |
| NCNN / MNN / PaddlePaddle / RKNN / IMX500 | 同名 | 国产端侧芯片 |

导出 ONNX 缺依赖会自动装 `onnx>=1.15`、`onnxslim>=0.1.59`、`onnxruntime`。

实测：`best.pt` → `best.onnx` **1.0 秒**，12,750,066 字节，输入 `images [1,3,640,640]`，输出 `output0 [1,9,8400]`（4 坐标 + 5 类）。

### 5.2 导出后接回自动标注

导出完成点 **应用 Apply**，软件会 `create_auto_labeling_config(...)` 生成一份 yaml 并直接 `load_custom_model_config`，**新模型立刻出现在自动标注的模型下拉框里**，不用手改配置。

手工路径（等价）：写一份 yaml + 注册进 `%USERPROFILE%\.xanylabelingrc` 的 `custom_models`。本项目已注册两条：

| 模型 | yaml | 权重 |
|---|---|---|
| PPE 工地安全帽/反光背心 (YOLOv8n) | `models\ppe_yolov8n.yaml` | `models\construction_ppe_yolov8n.onnx`（10 类，含口罩/锥桶/机械/车辆） |
| PPE 演示训练模型 (YOLOv8n, 8 轮 CPU) | `models\ppe_demo_trained.yaml` | `models\demo_trained_yolov8n.onnx`（5 类，训练产物副本） |

yaml 模板：

```yaml
type: yolov8
name: ppe_demo_trained_yolov8n
provider: Ultralytics
display_name: PPE 演示训练模型 (YOLOv8n, 8 轮 CPU)
model_path: demo_trained_yolov8n.onnx   # 相对本 yaml 所在目录（models/）
conf_threshold: 0.35
iou_threshold: 0.45
classes:            # 顺序 = 训练时的 names 顺序，不能乱
  - 安全帽
  - 未戴安全帽
  - 未穿反光背心
  - 人
  - 反光背心
filter_classes:
  - 安全帽
  - 未戴安全帽
  - 反光背心
  - 未穿反光背心
  - 人
```

⚠️ **保存 yaml 必须是 UTF-8 无 BOM**。带 BOM 时 PyYAML 能读，但类别名首字符会变成 `\ufeff安全帽`，导致该类全部匹配失败、静默丢框。

### 5.3 实测：新模型在软件里的表现

用 X-AnyLabeling 自己的 `YOLO` 类加载 `ppe_demo_trained.yaml`，跑 demo2 前 5 张：

| 图 | 耗时 | 框数 | 检出 |
|---|---|---|---|
| 1 | 54 ms | 2 | 安全帽 1、人 1 |
| 2 | 48 ms | 8 | 安全帽 3、人 3、反光背心 2 |
| 3 | 45 ms | 10 | 反光背心 3、人 4、未戴安全帽 1、安全帽 2 |
| 4 | 48 ms | 10 | 人 5、反光背心 2、未穿反光背心 1、安全帽 2 |
| 5 | 45 ms | 27 | 安全帽 9、未穿反光背心 6、人 9、未戴安全帽 3 |

平均 **48 ms/张**，中文标签全部正确，说明「训练 → 导出 ONNX → 接回自动标注」这条链是通的。

## 6 导出标注（数据集交付用）

菜单：**导出 Export › YOLO HBB**（水平框；旋转框选 `YOLO OBB`，分割选 `YOLO Seg`）。

| 步骤 | 操作 | 坑 |
|---|---|---|
| 1 | 选类别文件 `classes.txt` | 每行一个类名，**顺序必须等于 data.yaml 的 names** |
| 2 | 选输出目录 | **不能**是图片目录或其子目录，也不能是它的父目录，否则报 `The export root directory cannot be the loaded image directory or one of its subdirectories.` |
| 3 | 确认 | 生成 `labels/*.txt`（`cls cx cy w h` 归一化） |

`classes.txt`（已备好，62 字节，无 BOM）：

```
安全帽
未戴安全帽
未穿反光背心
人
反光背心
```

⚠️ **不在 classes.txt 里的标签会被静默丢弃**——不报错，直接少框。导完一定抽查框数。

⚠️ `classes.txt` 用 PowerShell `Set-Content -Encoding UTF8` 会带 BOM → 第一个类 `安全帽` 整体丢失。必须用无 BOM 写入。

## 8 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 训练报 `torch_missing` | `Environment:` 留空或指向没装 torch 的解释器 | 填 `<装了 torch+ultralytics 的 python.exe>` |
| 训练报 `ultralytics_missing` | 同上，缺 ultralytics | `uv pip install ultralytics --python <装了 torch+ultralytics 的 python.exe>` |
| 训练一开始就 CUDA 报错 | `Device:` 选了 cuda，本机无 CUDA 工具链 | 改成 `cpu` |
| 导出 yolo 后框大量缺失 | `classes.txt` 有 BOM，或类别顺序不对，或标签不在表中 | 用无 BOM 重写，核对顺序 |
| 导出报路径错误 | 输出目录和图片目录重叠 | 换一个无关目录 |
| 画完框卡死不响应 | 图片目录 ACL 只读，CPython 3.12 `tempfile` 无限重试（已打补丁 fail-fast） | 换可写目录，或 `文件 › 更改输出目录` |
| 模型下拉框里看不到新模型 | 没注册进 `custom_models` | 导出后点「应用」，或手改 `%USERPROFILE%\.xanylabelingrc` |
| 自动标注把旧标注覆盖了 | 设计如此 | 批量前备份 json |

```

File>Open Dir → 画框 R/改标签 → AI 标注跑一遍 → Train>Ultralytics → Export>ONNX  → 自动出现在
Ctrl+U            Ctrl+E 保存      再人工修       Environment=      1 秒 / 12.7MB    模型下拉框
                                                  <你的环境>\...python
     ↓                ↓                 ↓              ↓                  ↓                ↓
 92 张已标图      1146 个框        模型预填         8轮/416px          best.onnx       48ms/张

```
