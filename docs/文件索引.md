## 6. 数据集文件命名规则

- 图片名形如 `ppe_0357_jpg.rf.050090d9456aba1025eed0758342caba.jpg`：`ppe_<序号>` + Roboflow 导出哈希。
- 演示集多了前缀 `test__`（表示来自 test 划分）。
- 标注与图片**同名不同扩展名**：
  - YOLO 格式 → `<同名>.txt`，内容 `cls cx cy w h`（归一化 0~1），类索引见 `data.yaml`；
  - X-AnyLabeling 格式 → `<同名>.json`，在图片同目录（只有 `demo/` 和 `demo2/` 有）。
- `classes.txt` 是 YOLO 导出用的类别表（UTF-8 **无 BOM**，带 BOM 会丢框）。

## 7. 已知的"看起来奇怪但其实正常"的地方

| 现象 | 原因 |
|---|---|
| `demo/images/` 里图片和 `.json` 混在一起 | X-AnyLabeling 的约定，标注放图旁边 |
| `demo/labels/` 的框数（533）比 `.json` 的 shape 数（599）少 | `.json` 里有超出 5 类的框（口罩/锥桶等），`prune_labels.py` 裁掉了 |
| `models/ppe_yolov8n.yaml` 里 `classes` 有 10 项但只报 5 类 | ONNX 输出通道固定 10 项，删了会错位；用 `filter_classes` 过滤 |
| `runs/` 目录在本地有、在 GitHub 上没有 | `.gitignore` 忽略；需要的 ONNX 已复制到 `models/` |
| `docs/demo_train_results.csv` 的 0.7168 看起来比 0.5401 高很多 | 口径不同：0.7168 是 416px / 25% 数据 / 8 轮在**验证集**上的演示值；0.5401 是 640px / 全量 / **测试集** × 10 类权重。**不能对比** |
| 控制台里中文显示成乱码 | 本机 PowerShell 默认 GBK。看文件请在编辑器里按 UTF-8 打开；`tools/test_xal_model.py` 已强制 UTF-8 输出 |
